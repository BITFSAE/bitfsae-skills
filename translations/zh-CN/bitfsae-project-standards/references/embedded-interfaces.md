## 1. 权威来源

按以下顺序交叉核对，并结合仓库调整：

1. 已批准的系统接口数据库或硬件设计；
2. 生成器输入，如 .ioc；
3. 应用源码与公开头文件；
4. 生成源码；
5. 正文文档。

发生冲突时，判断是生成过期、自定义代码有意覆盖生成值，还是文档错误。说明原因，不要静默选择其一。

## 2. STM32 与生成代码

- 修改时钟、引脚、外设、DMA、NVIC 和生成器拥有的设置应在 CubeMX 或相应生成器输入中完成。
- 对生成 C/H 文件的自定义内容只放在保留用户区域。
- 重要逻辑放入独立模块，并配小型公开头文件。
- 再生成后验证：自定义源文件仍在构建列表、用户区域仍然保留、中断钩子仍调用应用处理函数、安全相关外设设置仍然生效。
- 生成器输出与配置不一致时，记录有意执行的初始化后寄存器修正。
- 再生成后验证 Debug 构建；交付、优化敏感代码或内存变化时也要验证 Release。

## 3. CAN 与 DBC

记录：总线波特率、帧类型、ID、方向、DLC、周期或事件触发、超时与所有者。每个载荷字段记录字节范围（需要时给位范围）、字节序、有无符号、比例、偏移、单位、合法范围、无效值与复位行为。

同时记录：

- 命令 CRC/校验参数和计算范围；
- 顺序与确认匹配；
- 命令有效期与重放/续期行为；
- 重试、邮箱满、总线关闭与丢帧行为；
- 信号新鲜度与回退策略；
- 目标值与实际输出；
- 配置是仅 RAM 还是持久化。

使用精确示例并验证计算。用消费项目实际使用的 C 或语言给出解析/打包代码。不要仅为方便加入不相关脚本语言示例。

保持 DBC 报文 ID、长度、字节序、有无符号、比例、单位、值表、节点方向和注释与代码一致。DBC 描述节点的完整接口时，同时包含接收和发送报文。明确标记需要上游核实的临时信号名。

共享接口仓库边界：工作改变对外消费的 CAN 帧 ID、收发节点、帧类型、DLC、信号布局、字节序、有无符号、比例、偏移、单位、范围、无效值、计数器、CRC、频率、超时、确认或兼容规则时，更新 BITFSAE/vehicle-interfaces。内部重构、合规恢复修复或项目专属配置不需要更新。

## 4. 其他硬件接口

对 UART、I2C、SPI、ADC、PWM、捕获、GPIO 和传感器，记录维护者或集成者需要知道的信息：

- 外设实例与引脚映射；
- 速度、模式、极性、上拉、电气反相和电压电平；
- 地址表示（包括 7 位与 HAL 移位的 I2C 地址）；
- 采样率、滤波、转换时间、超时与标定；
- 单位、符号方向、饱和与断开值；
- PWM 映射或每转脉冲数等物理公式。

板级事实放在硬件文档，可复用驱动契约放在公开头文件，常改应用值放在配置文档。

## 5. 通用配置

对常改值使用命名定义：ID、周期、超时、阈值、标定、控制曲线、变化率、回退值和地址分配。名称允许时包含单位。

配置文档必须告诉维护者：

- 哪些可以安全修改；
- 在哪里修改；
- 允许范围和相互关系；
- CAN 命令能否覆盖它，以及覆盖是否在复位后保留；
- 必须同步更新的接口、测试、标定或硬件。

## 6. 时序、中断与故障处理

记录主循环周期、中断驱动输入、共享数据处理、超时与启动顺序。保持中断处理函数简短，繁重工作交给应用代码。

对车辆控制与监控，定义以下行为：缺失传感器、过期报文、无效数据、外设启动失败、总线关闭、发送队列满、看门狗复位与重启。优先使用有界等待。区分安全回退与正常控制、手动测试模式。

描述诊断位时，必须说明何时置位、何时清除，以及是否影响控制输出。

## 7. 验证

按需验证：

- 生成器配置与生成初始化；
- 源码常量与文档、DBC；
- 示例帧、CRC、有符号值、缩放与无效标记；
- 自定义模块是否进入构建；
- Debug 与 Release 构建；
- 静态警告与内存使用；
- 台架用例：启动、正常工况、缺少输入、畸形命令、超时、恢复与复位；
- 文档链接与版本控制整洁度。

未完成的硬件测试写入 CHANGELOG.md，不要暗示已通过。
